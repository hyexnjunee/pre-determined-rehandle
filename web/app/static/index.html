반대편 크레인이 Rehandle을 도와주면 얼마나 좋아질까

작업 순서가 정해진(predetermined) twin crane 블록에서, 반출·적하 전에 필요한 rehandle을 반대편 크레인이 대신 해주는 협업 모델과 지금처럼 원래 크레인이 다 하는 비교군을 같은 인스턴스로 돌려 비교합니다. 두 모델 모두 model/ 폴더의 노트북을 그대로 실행합니다.

노트북 연결

모델은 계속 노트북에서 고치면 됩니다. 웹은 실행할 때마다 노트북을 읽어서 아래 지점만 바꿔 넣습니다.
  • 데이터 셀: N_BAY, Seq_SC = {…}, Seq_LC = {…}
  • 파라미터 셀: safety_margin t_hat pick drop rh_inplace OBJ (협업 모델은 ALLOW_ASSIST HOME_RH_FIXED)
  • 솔브 셀: model.Params.TimeLimit, model.optimize()
  • 시각화 셀: crane_colors = { 가 있는 셀 (실패해도 해는 유지)
이 이름들만 그대로 두면 웹이 자동으로 따라갑니다.

작업 구성
Rehandle
트럭 도착 간격 소수 가능 · 0 이면 모두 처음부터 도착
생성
LD·GO 마다 "RH 발생 확률" 로 rehandle 이 붙고 개수는 1~최대 개수. 각 rehandle 은 "다른 bay로 옮길 확률" 로 ±거리 상한 안의 다른 bay 에, 나머지는 같은 bay 안에 내려놓습니다. 트럭은 모든 작업에 있습니다 (DS·LD 내부 트럭, GI·GO 외부 트럭). 도착 시각은 크레인 순서를 따르고, 평균 간격은 위 값입니다 (일정 간격 / 간격이 지수분포인 무작위 / 몇 대씩 한꺼번에 도착). 참고 (동원 2025-01 데이터): GO 의 51.95%에 rehandle, 평균 2.32개, 같은 bay 28.5%, 이동 거리 중앙값 4 bay. 2개 이상 만들면 인스턴스 목록에 바로 저장됩니다.
실데이터 가져오기
구간 안에서 시작한 DS·LD·GI·GO 를 크레인별 실제 순서대로 가져옵니다. rehandle 개수는 RH_CNT, 목적 bay 는 직전 AH 의 도착 bay 입니다. LD(적하) 의 RH_CNT 는 2025-02-08 12:04 부터 기록돼 있어, 기록이 빈 LD 는 직전에 같은 블록·bay·row 에서 연달아 한 AH(간격 ≤ 10분)로 추정합니다 (기록과 개수 일치 99.3 %, 발생 정밀도 96.7 % · 재현율 87.0 %). 트럭 도착 a 는 REQ_DT (구간 시작 기준 초), 시간 파라미터는 초 단위 실데이터 값(t̂ 1.5 · pick 75 · drop 75 · ρ 150)입니다. 안전 여유는 현장 값이 정해지면 바꾸세요.
